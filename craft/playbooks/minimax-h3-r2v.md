# MiniMax H3 R2V 플레이북 (얼굴 없는 쇼츠용)

이 문서는 MiniMax H3 Reference-to-Video의 **프롬프트 문법, 반복 실패 유형과 대응**을 소유한다.
워크플로 설정은 `library/workflows/h3-r2v-speedx6/README.md`, 실행 절차는
`docs/runbooks/local-generation.md`, 제작 기준은 `craft/doctrine/shorts-format.md`.

근거: SpeedX6 워크플로의 "R2V Prompt Guide" 노트, 이후 15편 넘는 실제 제작 기록(2026-10~11).
**(미검증)**은 아직 실제로 시험하지 않은 내용이다.

기준일: 2026-11-10

---

## 1. 생성 단위

- **블록 = 나레이션 한 턴 = 장면 1~2개.** 장면 하나를 클립 하나로 만든다. 장면이 둘이면 클립 둘(`B02a/B02b`).
- **클립 길이 7~8초(175~192프레임)가 표준이다.** 10초(243프레임) 이상은 생성하지 않는다. PC가 멈추고 ComfyUI가 종료된 기록이 두 번 있다.
- 편집에 쓸 길이와 생성 길이는 따로 둔다. 짧게 쓰는 블록도 7초로 생성하고 앞부분을 쓴다(§6).
- 카메라 이동(밀기·당기기·팬)은 생성에서 지시하지 않는다. 조립에서 편집 줌으로 만든다.
- 한 클립 안을 `[Shot n]`과 타임스탬프로 여러 컷으로 나누는 방식은 기본으로 쓰지 않는다. 원본 노트는 ±0.25초를 지킨다고 하지만 **(미검증)**.

## 2. 레퍼런스 배치 (최대 9장, 적을수록 빠름)

| 순서 | 내용 | 비고 |
|---|---|---|
| `<Picture 1>` | 그 블록의 대표 그림(768×1344로 변환) | 화풍·구도의 기준 |
| `<Picture 2~>` | 캐릭터 기준 그림, 반복 소품 | 필요한 것만 |

- 대표 그림은 `craft/playbooks/gpt-image.md`로 만든 9:16 그림을 768×1344로 맞춘다(비율이 다르면 가운데 자르기·흐린 띠로 넓히기, 늘이지 않음).
- 모든 레퍼런스에 **임무 문장**을 하나씩 준다(정체성 / 장소 / 스타일 중 하나). 임무 밖의 요소는 거의 옮겨지지 않는다.
- 레퍼런스가 텍스트보다 강하다. 바꿔야 하는 것은 프롬프트가 아니라 레퍼런스 그림을 고친다.
- `ref_image_size`는 `match`(기본값, 빠름). 정체성이 흔들릴 때만 `max`를 시험한다.

## 3. 프롬프트 형식 — 여섯 섹션 (이름·순서 고정, 영어)

워크플로가 읽는 형식이다. `jobgen.py`가 여섯 섹션이 모두 있는지 검사한다.

```
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

- **subject_definitions**: 재사용하는 것 한 줄씩. 스타일 자체도 Subject로 둔다.
  - 예: `<Subject 1> is the art style of <Picture 1>: {이 편의 공통 스타일 문장}.`
- **summary**: `[reference generation]`으로 시작하고, 영상 내용과 레퍼런스 대응을 1~2문장으로.
- **retention_analysis**: Subject마다 고정할 점. 인물·물체는 두 문장 정체성 고정.
  - 예: `<Subject 2>: fully_preserved - remains the exact same object from <Picture 2>, preserving its shape, proportions, colors and markings. The preserved identity covers its form and surface, while the shot freely directs its position and small movement.`
- **detailed_description**: 전역 문장(스타일·조명·고정 카메라)으로 시작하고, 화면 속 위치·작은 동작 하나·눈에 보이는 결과를 쓴다.
- **overall_soundscape**: 화면 사건의 효과음만. 음악은 넣지 않는다(클립 오디오는 기본으로 쓰지 않음).
- **non_diegetic_music**: 항상 `N/A`.

### 내용 점검 6항목

프롬프트를 쓰고 나면 아래 여섯 가지가 모두 들어 있는지 본다(양식: `productions/_template/BRIEF.md` §5).

| 항목 | 들어갈 섹션 | 내용 |
|---|---|---|
| Style | subject_definitions, detailed_description 첫 문장 | 선·재질·색·배경을 구체적으로. 이 편의 공통 스타일 문장 |
| Keep | retention_analysis | 그 그림에 **실제로 있는** 인물·소품·공간만 |
| Action | detailed_description | 시작 구도와 눈에 보이는 작은 동작 하나 |
| Camera | detailed_description 전역 문장 | `A locked-off static camera faces the scene straight-on for the whole video.` |
| Stability | retention_analysis, detailed_description | 모양·위치·색·조명 유지, 사라지거나 새로 생기는 것 없음 |
| Avoid | detailed_description 끝 (짧게) | 글자·라벨, 새 인물·손·펜, 말소리·음악 |

## 4. 얼굴 없는 내레이션 쇼츠 전용 규칙

- **대사(`<d>`)를 쓰지 않는다.** 인물은 긍정문으로: `The figures stay silent with closed mouths and communicate only through gestures and posture.`
- **고정 문장은 블록별로 쓴다.** 편 공통 문장에 사물을 넣으면 그 사물이 없는 블록에도 생긴다. 스타일 문장에도 그 블록에 있는 요소만 넣는다.
- **인물 설명은 그림과 같게.** 그림과 다르게 쓰면 그림을 바꾼다(없던 머릿수건 생성 사례).
- **위치를 못 박는다.** '밥그릇에서만 김'이라고만 쓰면 옆 접시에서도 김이 난다. "화면 오른쪽 그릇 바로 위, 왼쪽 접시 위 공기는 맑게"처럼 쓴다.
- **글자 금지:** 간판·라벨은 빈 면으로(`blank labels with no markings`). 글자는 후반 합성.
- **하단 20%는 비운다:** 핵심 피사체는 위쪽 약 60% 안.
- 부정어는 적게 쓴다. 금지 단어가 문맥에 남으면 오히려 나올 수 있다.
- 실제 브랜드·실존 인물·작품명은 쓰지 않는다.

## 5. 자주 나오는 변형과 대응

| 현상 | 대응 |
|---|---|
| 첫 0.2~1초에 소품이 빠지거나 화면 밖에서 미끄러져 들어옴 (자주) | `start_frame`으로 앞을 잘라 씀(12~30프레임) |
| 첫 0.4초에 물체가 하나 더 떨어지는 등 순간 복제 | 시작 시점을 뒤로 |
| 벽에 걸린 그림·차트가 3초 뒤 사라짐 | 앞부분만 + 정지 |
| 해(원반)가 일몰처럼 움직임 | 해 영역을 첫 프레임 패치로 고정, 또는 정지 컷 |
| 책 페이지가 들리고 위에 놓인 카드까지 움직임 | 떨어진 요소(수면·빛)만 움직이게 |
| 늘어지는 물질(엿·리본)이 반드시 흘러내림 | 앞 2.5~4초 + 정지. 참조 그림에서 늘어진 부분 제거 |
| 잉크 원이 검게 채워짐 ("never fills"로 못 막음) | 앞부분만 |
| '화면이 밝아짐'·'반사' 지시가 화면 전체 색 전환으로 커짐 | 그런 지시를 빼거나 앞 1.5~3초만 |
| '빛이 옷감 위를 지나감' 지시가 옷 색을 바꿈 | "조명·색 그대로, 해가 밝아지거나 움직이지 않음" |
| '더 가까이(reframe)' 지시를 무시하고 사람이 사라진 장면 생성 | 구도 변경은 편집 줌으로 |
| 좌우 18px 검은 띠(필러박스) | QC에서 열 평균 밝기로 검출. 편집 줌 1.3배 이상이면 가려짐 |
| 번짐(워시) 요소가 6초 뒤 사라짐 | 앞 5초만 |
| 'pulse' 지시를 주면 대상이 사라졌다 나타남 | "tiny bounce, stays fully drawn, never fading" |
| 콜라주·디오라마 구도를 재해석(카메라 회전·기울기 변화) | 편집 줌 좌표는 생성 클립 기준으로. 구도가 중요하면 I2V(→ `minimax-h3-i2v-turbo.md`) |
| 4~6초 뒤 형태 변화(모자 생김, 표정 바뀜) | 그 전에 컷 |
| 글자처럼 보이는 낙서(G·e·9·© 모양 나선, 라벨의 'L') | 아래 처리 방법 |
| 1.6배 이상 빠르게 + 프레임 블렌딩 → 잔상·반투명 | 바운스는 편집 스케일로 |
| 같은 입력 재실행 시 캐시된 결과가 그대로 나옴 | seed를 바꾼다 |

글자처럼 보이는 낙서 처리:
1. 쓰는 모든 컷의 작은 고립 획을 모아 한 장의 검사 시트로 만든다(채도 기준과 배경 대비 기준 둘 다).
2. 정지 컷의 낙서는 `patch`로 지운다.
3. 클립에서 위치가 고정된 낙서는 ffmpeg `delogo`(여러 프레임에서 잰 합집합 + 여백 6px)로 지워 `<클립>_clean.mp4`로 새로 저장한다.
4. 움직이는 물체 안의 낙서는 참조 그림에서 지운 뒤 클립을 다시 만든다.

**잘 되는 동작:** 작은 '톡 튀기', 김·반짝임, 손짓·끄덕임, 붓기, 망치질, 공이 굴러 들어가기, 지구본 회전(4초 전까지).

## 6. 불합격 클립 대응 순서

1. **앞부분만 쓰기:** 앞부분만 쓰고 나머지는 정지 화면으로 채운다. 대부분의 변형은 2~4초 뒤에 시작한다.
2. **속도 조절:** 구간 속도를 0.5~0.94배로 늦추거나, 왕복·역재생한다.
3. **재사용:** 같은 참조 그림의 합격 생성분을 인접 컷에 다시 쓴다(역재생 포함).
4. **참조 그림 수정:** 문제 요소를 지우거나 모양을 바꾼 뒤 다시 생성한다.
5. **프롬프트 수정:** 프롬프트를 고치고 seed를 바꿔 한 번만 다시 생성한다.
6. **방식 전환:** 구도가 중요하면 I2V로 바꾸거나, 정지 화면 + 편집 줌으로 처리한다.

seed만 계속 바꾸는 것은 마지막 수단이다. 대체한 컷은 `renders.md`에 적는다.

## 7. 시간·자원 (RTX 5070 12GB 기준)

- 클립당 약 5~7분, 첫 클립은 8~10분. PC RAM 여유가 적으면 더 느려진다(13클립에 약 75분 사례).
- 디스크 여유가 30GB 미만이면 `No space left on device`와 `HostBuffer.read_file_slice failed`가 섞여 나온다.
- H3는 한 번에 하나만. 여러 클립은 큐에 순서대로 넣는다.
