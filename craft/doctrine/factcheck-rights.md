# 팩트체크·권리 정책

이 문서는 **주장 검증 절차, 자료 등급, 확신도별 표현, 권리·표시 기준, 정정 절차**를 소유한다.
내부 운영 정책이며, 법적 허용 범위나 AI 권리를 보증하지 않는다.

기준일: 2026-11-10

---

## 1. 주장 검증 절차

1. **주장을 쪼갠다.** 대본의 사실을 `F01`부터 하나씩 나눈다. '최초', 연도, 장소, 발명자, 인과관계는 각각 별도 주장이다.
2. **출처 수를 맞춘다.**
   - 핵심 기원·어원·최초 주장: 서로 독립적인 출처 2개 이상. 그중 1개는 원자료나 학술·전문기관 자료.
   - 단순 정의·공식 규격: 해당 기관 1차 출처 1개면 된다. 확인일을 적는다.
3. **실제 구절을 읽는다.** 해당 구절·쪽수·날짜·원문 의미를 확인한다. 검색 요약만 읽었으면 '본문 미확인'이다. 같은 원저자를 재인용한 사이트는 10개여도 근거 1개다.
4. **입증 범위를 구분한다.** '발견', '명명', '특허', '대중화', '현존 최초 기록'은 각각 다르다. 자료가 최초 기록만 입증하면 최초 발명으로 바꾸지 않는다.
5. **반론을 찾는다.** 아래 확신도에 맞춰 표현을 줄인다. 근거가 없으면 재미있는 주장이라도 뺀다.
6. **전체를 함께 검사한다.** 대본·화면·제목·자막·썸네일·설명을 같이 본다. 날짜가 맞아도 생성 그림 속 도구가 시대와 다르면 고친다.

## 2. 자료 등급

| 등급 | 자료 | 쓰는 범위 |
|---|---|---|
| A | 원자료·공식기관 (규정·특허·당대 문헌·유물 정보) | 핵심 근거. 당대 기록도 오류·관점이 있는지 검토 |
| B | 학술·전문 연구 | 기원 해석의 핵심 근거. 연구 방법과 후속 반박 확인 |
| C | 전문 백과·사전·박물관 해설 | 교차검증·정의·출발점. 어원은 어원 전문 자료 우선 |
| D | 주요 언론 | 현대 취재 사실의 보조. 역사 기원은 인용한 연구까지 추적 |
| E | 블로그·SNS·위키·AI | 검색 단서로만 쓴다. 단독 결론 근거로 쓰지 않는다 |

## 3. 확신도별 대본 표현

| 확신도 | 대본 표현 예 | 화면 |
|---|---|---|
| 확인된 사실 | "이 문서에는 …라고 기록돼 있어." 범위를 특정한다 | 단정 가능 |
| 유력 | "지금 가장 유력한 설명은 …야." 유력하다는 근거도 필요 | '가장 유력한 설' 표지 |
| 복수설 | "A라는 설명과 B라는 설명이 있어. 기록으로는 …까지 알 수 있어." | 두 설을 나란히 |
| 속설·전설 | "전설에서는 …라고 전해져. 실제 기록과는 달라." | '전해지는 유래설'·물음표 |
| 미확인 | 본문에서 뺀다. 설명란에 "여러 설이 있다"로만 | — |

'확인된 사실'은 영구 불변 선언이 아니다. 새 근거가 나오면 다시 판정한다.

---

## 4. 유래 주제 특유의 함정

- **민간 어원:** 지금 발음이 비슷하다는 이유만으로 연결하지 않는다. 최초 표기, 음운 변화, 시대 간격을 확인한다.
- **순환 인용:** 링크를 거슬러 올라가 공통 원자료를 찾고, 독립 출처 수를 다시 센다.
- **위키 단일 의존:** 각주의 원문을 읽고, 전문기관·사전으로 교차 확인한다.
- **번역:** 원문 용어·주어·시제·추정 표현을 대조한다. 'may' 같은 추정을 사실 단정으로 옮기지 않는다.
- **전설의 시각화:** 전설 장면은 '전설의 재현'으로 표시한다. 스타일 비교에는 사실 논란이 없는 사물 장면을 쓴다.

AI의 자기검토와 사람(운영자·전문가) 검토는 구분해서 기록한다. 출처는 서지와 짧은 발췌 중심으로 보관하고, 유료 원문 전체를 다시 배포하지 않는다.

## 5. 권리·표시 기준

| 대상 | 기준 |
|---|---|
| 그림·클립 | 생성물(로컬 ComfyUI, 승인된 유료 생성)을 쓴다. 실사 사진은 쓰지 않는다(운영 선택). 다른 도구는 운영자가 허용할 때만 |
| 음악 | ACE-Step 1.5 생성곡(MIT 라이선스, 모델 카드에 상업 이용 허용 명시) 또는 코드 합성음. 외부 곡을 쓰면 곡별 출처 표기·기간·플랫폼 범위를 기록한다. '무료'·'AI 생성'만으로 무제한 이용을 가정하지 않는다 |
| 폰트 | 배포처 라이선스와 영상·상업 이용 범위를 확인하고 기록한다(`_infra/shorts-tools/fonts/README.md`) |
| 목소리 | 운영자 본인 또는 사용 허락을 받은 보이스만 쓴다. 타인의 목소리를 무단 복제하지 않는다 |
| 로고·인물·캐릭터 | 제3자 로고, 실존 인물 얼굴, 유명 캐릭터는 생성하지 않는다. 꼭 필요하면 제공받은 파일과 사용 근거(브랜드 가이드 등)를 확인한다 |
| 직접 인용 | 꼭 필요한 최소량만, 출처와 인용 표시, 자체 설명을 붙인다. '몇 초·몇 글자까지 합법' 같은 공통 안전선은 만들지 않는다 |
| 브랜드 | 이름의 사실 설명과 후원·공식 제휴를 구분한다. 허위 제휴 암시와 로고 재현을 피한다 |
| AI 표시 | 설명란에 AI 사용 고지를 넣는다. 현실처럼 보이는 재현이면 YouTube '변경되거나 합성된 콘텐츠' 표시를 게시 시점에 판단한다. 설명란 고지가 Studio 설정을 대신하지 않는다 |
| 모델 라이선스 | 클립·이미지 모델의 라이선스(제외 지역·상업 이용 조건)를 확인한다. 제한이 있으면 사용 여부는 운영자가 결정해 `private/decisions.md`에 남기고, 게시 직전 변경 여부를 다시 확인한다 |
| 대량 생산 | 자체 조사·해석·장면 설계가 없는 반복 대량 제작을 하지 않는다. 생성물이라는 사실만으로 수익화가 보장되지 않는다 |

1분 넘는 쇼츠에 저작권 클레임이 걸리면 재생·추천·수익화에 영향이 있다. 공개 전 비공개 업로드로 저작권 검사를 확인한다.

---

## 6. 정정 절차

1. 오류 제보를 받는다.
2. 근거를 확인한다.
3. 영향을 받는 대본·설명·자막·영상을 찾는다.
4. 정정본과 조치안(설명란·고정 댓글 수정 / 영상 교체·재게시)을 준비한다.
5. 운영자 승인을 받는다.
6. 버전과 정정 이유를 `renders.md`에 남긴다.

- 심각한 오정보는 운영자에게 즉시 알리고 비공개 전환을 제안한다.
- 조회수가 낮다는 이유로 영상을 삭제해 기록을 잃지 않는다.
