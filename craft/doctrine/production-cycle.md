# 제작 사이클 — 한 편의 단계와 승인 지점

이 문서는 모델과 무관한 **한 편 제작 단계(0~11), 작업 위치와 분담(ChatGPT → Claude 인계), 승인 지점,
요청 범위별 납품 기준, 수정 영향 범위**를 소유한다.

- 0~6단계의 실행 방법 → `craft/doctrine/planning.md`
- 사양·연출·판정 기준 → `craft/doctrine/shorts-format.md`
- 팩트체크·권리 → `craft/doctrine/factcheck-rights.md`
- 성과·회고 → `private/analytics.md` (비공개. 항목 안내는 `private/README.md`)
- 실행 절차 → `docs/runbooks/`
- 채널 고유 값(채널명·타깃·보이스·저장소 이름) → `private/channel.md` (없으면 `config/channel.example.md`)

"대표"는 채널 운영자이자 최종 결정자다.

---

## 1. 어디서 무엇을

한 편은 **기획(ChatGPT) → 인계 → 제작(Claude)** 순서로 간다. 두 쪽은 같은 `AGENTS.md`를 읽고,
작품 폴더 `productions/<종류>/<작품>/`의 `BRIEF.md`와 `생성상태.md`를 주고받는다.

| 어디서 | 하는 일 | 도구 |
|---|---|---|
| 기획 — Codex (ChatGPT 계정 로그인, 이 폴더) | 0~5단계: 주제·조사·대본·블록·스타일 시안·대표 그림·콘티·프롬프트 (= 정적 제작 패키지), 메타 초안 | Codex 웹 검색, ChatGPT 이미지 생성(`craft/playbooks/gpt-image.md`), 작품 폴더 |
| 기획 — 어디서나 (웹 화면) | 주제 후보·회차 목록·상태 확인 | claude.ai 아티팩트 — **설계만 있음**(`docs/design/web-console.md`) |
| 제작 — Claude (Claude Code, 운영자 PC) | 6~9단계: 나레이션, 시험 클립, 클립 생성, 조립·검수, 썸네일·납품 | comfy-mcp, 힉스필드 MCP, Codex 이미지 생성 도구, PC 셸 (`docs/runbooks/local-generation.md`) |
| 유료 생성 (힉스필드) | 나레이션 | 크레딧 사용 — 매번 승인 (`docs/runbooks/paid-generation.md`) |
| 그림 생성 (Codex) | 스타일 시안·대표 그림(4~5), 썸네일 바탕(9) | ChatGPT 요금제 사용량 — 장수를 알리고 승인 (`craft/playbooks/gpt-image.md`) |
| 에피소드 정본 저장소 (Google Drive) | 편별 폴더: 기획 사본, 대표 그림, 최종본, 썸네일, 업로드 메타 | Drive 커넥터, PC 동기화 폴더 |
| 클라우드 작업 공간 | 나레이션 분할, 조립(편집 줌·자막·그래픽·믹스), QC, 썸네일 글자 합성 | ffmpeg, faster-whisper, Python |

- **편별 기획·상태의 정본은 작품 폴더다.** 지금 단계·담당·인계 상태는 `생성상태.md` 맨 위 기계용 상태 블록이 소유한다(형식: `_infra/episode-state/README.md`). 어느 쪽이든 작업을 시작하면 그 블록부터 읽고, 끝나면 고친다.
- **6단계 이후(영상 제작)는 PC에서 ComfyUI를 쓸 수 있을 때만 시작한다.** Claude는 이어받을 때 `docs/runbooks/local-generation.md` §1 점검을 먼저 한다. 쓸 수 없으면 상태를 `waiting_pc`로 두고 멈춘다. 그동안 ChatGPT 쪽은 다른 편의 0~5단계를 진행할 수 있다.
- 다른 기획 공간(Claude 프로젝트 채팅 등)에서 기획해도 결과는 같은 작품 폴더와 상태 블록에 같은 형식으로 남긴다.
- 그림·영상 파일의 정본은 에피소드 저장소다. ChatGPT가 만든 그림은 먼저 작품 폴더에 저장하고 인계 뒤 Claude가 올린다. ComfyUI 중간물은 PC에 두고 채택본과 최종본만 올린다.
- 클라우드 작업 공간은 세션이 바뀌면 사라질 수 있다. 조립·검사 스크립트는 편마다 tgz로 묶어 에피소드 폴더에 남긴다.

### ChatGPT → Claude 인계 (5단계 → 6단계)

**넘기는 쪽(ChatGPT)** — 대표가 대표 그림을 승인하면 아래를 채우고 넘긴다.

| 확인 | 내용 |
|---|---|
| `BRIEF.md` | §2 브리프, §3 팩트체크 판정, §4 승인된 대본 버전(발화용·화면용), §5 블록표·공통 스타일 문장·블록별 콘티·시나리오·클립 프롬프트·연결표·타임라인 가안 |
| 그림 | 스타일 시안·기준 그림은 작품 폴더 `04_화면설계/`, 대표 그림은 `05_제작/대표이미지/<EP>_Bxx_representative.png` (블록마다) |
| 대표 선택 기록 | 주제·대본·스타일·대표 그림 승인이 `생성상태.md`에 날짜와 함께 있음 |
| 상태 블록 | `stage=5`, `status=handoff_ready`, `assignee=claude`, `handoff.status=ready`, `versions`(대본·스타일·대표 그림), `block_count` |
| 자동 검사 | `python _infra/episode-state/episode_state.py check <작품 경로> --handoff` 통과 |

**받는 쪽(Claude)** — 대표가 "이어서: EP###"라고 하면:

1. planning §0 재개 점검: 상태 블록 → `생성상태.md` → `BRIEF.md` 순서로 읽고, 인계 검사를 다시 돌리고, 대표 그림을 모두 열어 planning §5 검수 기준으로 본다.
2. 로컬 점검(`local-generation.md` §1)으로 ComfyUI를 쓸 수 있는지 확인한다.
3. 결과에 따라 상태 블록을 고치고 `생성상태.md` 인계 기록에 한 줄 남긴다.

| 결과 | 상태 블록 |
|---|---|
| 통과, PC 사용 가능 | `handoff.status=accepted`, `stage=6`, `status=active`(또는 나레이션 승인 대기면 `waiting_operator`) |
| 통과, PC 사용 불가 | `handoff.status=accepted`, `stage=6`, `status=waiting_pc` |
| 빠진 것·불일치 | `handoff.status=returned`, `stage=5`, `status=active`, `assignee=chatgpt`, `handoff.note`에 이유 |

- Claude는 ChatGPT 쪽에서 대표가 승인한 창작 결정(대본·스타일·대표 그림)을 임의로 바꾸지 않는다. 로컬 제약 때문에 바꿔야 하면 대표에게 묻고 기록한다.
- 인계 뒤 대본·그림을 고쳐야 하면 Claude가 직접 고치지 않고 `returned`로 되돌리거나, 대표가 지시한 범위만 고치고 기록한다.

## 2. 단계표

| # | 단계 | 담당 | 다음 단계로 넘길 결과물 | 대표가 하는 일 | 상세 |
|---|---|---|---|---|---|
| 0 | 재개 점검 | 이어받는 쪽 | 상태 3~5줄(쓸 버전·빠진 입력·시작 단계) | — | planning §0 |
| 1 | 주제 발굴 | ChatGPT | 후보 비교표, 브리프, 작품 폴더·상태 블록 생성 | **주제 선택** | planning §1 |
| 2 | 조사·팩트체크 | ChatGPT | 주장별 팩트체크(F01~), 자료 목록 | — | planning §2, factcheck-rights |
| 3 | 대본 | ChatGPT | 대본 vNN(발화용·화면용), 예상 길이, 평가 | **대본 승인** | planning §3, shorts-format §2 |
| 4 | 블록·스타일 | ChatGPT | 블록표, 같은 블록 3~5화풍 동시 생성·비교, 스타일 기준 | **생성 승인 → 스타일 선택** | planning §4, shorts-format §3 |
| 5 | 대표 그림·콘티·프롬프트 | ChatGPT → 인계 | 블록별 대표 그림, 콘티·시나리오, 클립 프롬프트, 타임라인 가안 (= 정적 제작 패키지), 인계 | **생성 승인 → 그림 승인** | planning §5, 위 §1 인계 |
| 6 | 음성·판정 기준·시험 | Claude (PC) | 나레이션 한 테이크, 실측 타임라인, 이 편 판정 기준, 시험 클립 1~2개 | **나레이션 크레딧 승인** | planning §6, shorts-format §5·§10 |
| 7 | 클립 생성 | Claude (PC) | 채택 클립, 렌더 기록 | — | local-generation, playbooks |
| 8 | 편집·검수 | Claude | 배경음악·효과음, 조립, 자동 QC, 독립 평가, 수정본 | 시사본 확인 | review-delivery, post-production |
| 9 | 썸네일·메타·납품 | Claude | 썸네일 4종 + 비교 시트, 업로드 메타, 납품(md5 확인), 제작기록 | **썸네일·제목 선택** | shorts-format §8·§9, review-delivery |
| 10 | 공개 | 대표 | 게시 기록 | **직접 게시 후 URL·시각 알려 주기** | factcheck-rights §6 |
| 11 | 성과·회고 | Claude | 성과 기록, 다음 실험 1개, 회차 목록 갱신 | **Studio 캡처·CSV 전달** (24시간·7일·28일) | private/analytics.md |

- 단계가 바뀔 때마다 상태 블록의 `stage`·`status`·`assignee`·`next_action`을 고친다.

- 대본이 고정되면 그림·콘티와 메타 초안을 함께 진행할 수 있다. 대량 렌더 전에는 실제 음성 길이와 시험 결과를 대조한다.
- 대표가 패키지(대본·그림·프롬프트)를 직접 주면 인계 체크리스트(§1)로 대조한 뒤 6단계부터 시작한다. 패키지 지시와 로컬 제약이 다르면 로컬 규격을 따르고 기록에 남긴다(예: 12초 클립 지시 → 8초 생성 + 편집 줌).
- "알아서 끝까지"면 굵게 표시한 항목만 묻고 진행한다. ChatGPT 쪽은 5단계 인계에서, Claude 쪽은 PC를 쓸 수 없으면 멈춘다. "정적 패키지까지"면 5단계 인계에서 멈춘다.
- 단계가 끝날 때마다 결과(표·그림·시트·영상)를 보여 준다.

### 편당 크레딧 사전 승인 (선택)

대표가 편을 시작할 때 "EP### 크레딧 상한 N"을 주면 그 범위 안의 생성은 다시 묻지 않는다.
상한을 넘을 것 같으면 멈추고 묻는다. 사용량은 `renders.md`에 남긴다.

## 3. 요청 범위별 납품 기준

| 요청 | 기본 납품 | 완료 증빙 |
|---|---|---|
| 주제 추천 | 후보표, 추천 이유, 메인 줄거리, 근거 후보 | 후보마다 질문·전개·근거 수준이 보임 |
| 리서치·대본 | 팩트체크, 대본, 읽기용 원고, 변경·평가 | 핵심 주장과 버전, 남은 확인 사항 표시 |
| 스타일 비교 | 같은 장면 비교 시안과 평가, 선택 기록 | 비교 파일이 실제로 열림 |
| 정적 제작 패키지 | 대표 그림, 대본·콘티·시나리오, 클립 프롬프트, 타임라인, 썸네일·메타 초안 | 그림·클립·프롬프트 번호가 서로 맞음 |
| 영상 제작 | 나레이션, 채택 클립, 최종 MP4, SRT, QC, 판정 | 전체 재생·규격·판정 확인 |
| 업로드 메타만 | 복사용 메타(필요 시 썸네일) | 실제 대본과 설명·출처·표현 범위 일치 |

상태는 `제안`, `대표 선택`, `제작 기준`, `실측 전`, `파일 검수 완료`, `공개 확인`, `미확인`처럼
구체적으로 쓴다. '완료' 대신 무엇을 어디서 확인했는지 적는다.

## 5. 자주 쓰는 요청 문장

| 요청 | 하는 일 |
|---|---|
| "새 편 주제 추천해줘" (분야·시즌 조건) | 1단계부터 |
| "새 편: <주제>" | 1단계(그 소재 안의 관점 비교)부터 |
| "<주제> 정적 패키지까지" | 1~5단계 |
| "<주제> 알아서 끝까지" | 1~9단계, 승인 항목만 질문 |
| "패키지로 제작" + 첨부 | 0단계 대조 후 6단계부터 |
| "인계: EP###" (ChatGPT 쪽) | 5단계 인계 체크리스트를 채우고 상태 블록을 `handoff_ready`로 |
| "이어서: EP###" | 0단계 → 그 편 상태 블록의 `next_action`·`pending_operator`부터 (인계 대기면 §1 받는 쪽 절차) |
| "상태 목록" | `episode_state.py list`로 모든 편의 단계·담당·인계 상태 |
| "검수만: EP###" | 8단계 독립 평가 |
| "썸네일·메타 다시: EP###" | 9단계 |
| "성과 기록: EP###" + Studio 캡처 | 11단계 |
| "에이전트 점검" | `docs/runbooks/local-generation.md` §1 점검 루틴만 실행하고 보고 |

## 6. 원칙

- 창작 방향(주제·스타일·대본)은 에이전트가 임의로 정하지 않는다. 후보와 근거를 보여 주고 대표가 고른다.
- 한 번에 하나의 변수만 바꿔 비교한다.
- 확인한 결과만 "됐다"고 말한다.
- 이야기가 바뀌면 `BRIEF.md`부터 고친다.

## 7. 새 작품 시작

`productions/_template/`의 세 파일을 `productions/<종류>/<작품>/`으로 복사해 시작한다.
상태 블록의 `episode`·`topic`·`updated_at`을 채우고 `episode_state.py check`로 확인한다.

| 파일 | 소유하는 것 |
|---|---|
| `BRIEF.md` | 기획: 후보·브리프, 팩트체크, 대본, 블록표·스타일, 블록별 콘티·프롬프트, 업로드 메타 |
