# 제작 사이클 — 한 편의 단계와 승인 지점

이 문서는 모델과 무관한 **한 편 제작 단계(0~11), 작업 위치, 승인 지점, 요청 범위별 납품 기준,
수정 영향 범위**를 소유한다.

- 0~6단계의 실행 방법 → `craft/doctrine/planning.md`
- 사양·연출·판정 기준 → `craft/doctrine/shorts-format.md`
- 팩트체크·권리 → `craft/doctrine/factcheck-rights.md`
- 성과·회고 → `private/analytics.md` (비공개. 항목 안내는 `private/README.md`)
- 실행 절차 → `docs/runbooks/`
- 채널 고유 값(채널명·타깃·보이스·저장소 이름) → `private/channel.md` (없으면 `config/channel.example.md`)

"대표"는 채널 운영자이자 최종 결정자다.

---

## 1. 어디서 무엇을

| 어디서 | 하는 일 | 도구 |
|---|---|---|
| 기획 작업 공간 (Claude 프로젝트 채팅, 어디서든) | 0~5단계, 9단계 메타 초안 | 웹 검색, 프로젝트 문서, Google Drive 커넥터 |
| 유료 생성 (힉스필드) | 스타일 시안·대표 그림·썸네일 바탕(GPT 이미지), 나레이션 | 크레딧 사용 — 매번 승인 (`docs/runbooks/paid-generation.md`) |
| 에피소드 정본 저장소 (Google Drive) | 편별 폴더: 기획 사본, 대표 그림, 최종본, 썸네일, 업로드 메타 | Drive 커넥터, PC 동기화 폴더 |
| 클라우드 작업 공간 | 나레이션 분할, 조립(편집 줌·자막·그래픽·믹스), QC, 썸네일 글자 합성 | ffmpeg, faster-whisper, Python |
| 운영자 PC (이 폴더) | 6~8단계: ComfyUI 생성(클립·배경음악), 생성 원본 보관 | comfy-mcp, PC 셸 (`docs/runbooks/local-generation.md`) |

- PC가 연결되지 않았으면 6단계 이후는 시작하지 않는다. 그동안 기획 단계만 진행한다.
- 글 산출물의 작업본은 기획 작업 공간 또는 작품 폴더 `BRIEF.md`에 두고, 단계가 끝나면 에피소드 저장소에 사본을 둔다.
- 그림·영상 파일의 정본은 에피소드 저장소다. ComfyUI 중간물은 PC에 두고 채택본과 최종본만 올린다.
- 클라우드 작업 공간은 세션이 바뀌면 사라질 수 있다. 조립·검사 스크립트는 편마다 tgz로 묶어 에피소드 폴더에 남긴다.

### ChatGPT 연계 방식 (선택)

ChatGPT 대화형 모델은 직접 호출할 수 없다. 대표가 그 단계의 글 작업을 ChatGPT에서 하고 싶으면:

1. 에이전트가 그 단계의 작업 지시문(현재 버전·입력·원하는 산출물 형식)을 만든다.
2. 대표가 ChatGPT에서 실행하고 결과를 붙여 넣거나 에피소드 폴더에 올린다.
3. 에이전트가 결과를 대조·검수해 반영하고 다음 단계로 간다.

## 2. 단계표

| # | 단계 | 다음 단계로 넘길 결과물 | 대표가 하는 일 | 상세 |
|---|---|---|---|---|
| 0 | 재개 점검 | 상태 3~5줄(쓸 버전·빠진 입력·시작 단계) | — | planning §0 |
| 1 | 주제 발굴 | 후보 비교표, 브리프, 에피소드 폴더 생성 | **주제 선택** | planning §1 |
| 2 | 조사·팩트체크 | 주장별 팩트체크(F01~), 자료 목록 | — | planning §2, factcheck-rights |
| 3 | 대본 | 대본 vNN(발화용·화면용), 예상 길이, 평가 | **대본 승인** | planning §3, shorts-format §2 |
| 4 | 블록·스타일 | 블록표, 같은 블록 3~5화풍 동시 생성·비교, 스타일 기준 | **크레딧 승인 → 스타일 선택** | planning §4, shorts-format §3 |
| 5 | 대표 그림·콘티·프롬프트 | 블록별 대표 그림, 콘티·시나리오, 클립 프롬프트, 타임라인 가안 (= 정적 제작 패키지) | **크레딧 승인 → 그림 승인** | planning §5 |
| 6 | 음성·판정 기준·시험 | 나레이션 한 테이크, 실측 타임라인, 이 편 판정 기준, 시험 클립 1~2개 | **나레이션 크레딧 승인** | planning §6, shorts-format §5·§10 |
| 7 | 클립 생성 | 채택 클립, 렌더 기록 | — | local-generation, playbooks |
| 8 | 편집·검수 | 배경음악·효과음, 조립, 자동 QC, 독립 평가, 수정본 | 시사본 확인 | review-delivery, post-production |
| 9 | 썸네일·메타·납품 | 썸네일 4종 + 비교 시트, 업로드 메타, 납품(md5 확인), 제작기록 | **썸네일·제목 선택** | shorts-format §8·§9, review-delivery |
| 10 | 공개 | 게시 기록 | **직접 게시 후 URL·시각 알려 주기** | factcheck-rights §6 |
| 11 | 성과·회고 | 성과 기록, 다음 실험 1개, 회차 목록 갱신 | **Studio 캡처·CSV 전달** (24시간·7일·28일) | private/analytics.md |

- 대본이 고정되면 그림·콘티와 메타 초안을 함께 진행할 수 있다. 대량 렌더 전에는 실제 음성 길이와 시험 결과를 대조한다.
- 대표가 패키지(대본·그림·프롬프트)를 직접 주면 6단계부터 시작한다. 패키지 지시와 로컬 제약이 다르면 로컬 규격을 따르고 기록에 남긴다(예: 12초 클립 지시 → 8초 생성 + 편집 줌).
- "알아서 끝까지"면 굵게 표시한 항목만 묻고 진행한다. "정적 패키지까지"면 5단계에서 멈춘다.
- 단계가 끝날 때마다 결과(표·그림·시트·영상)를 보여 준다.

### 편당 크레딧 사전 승인 (선택)

대표가 편을 시작할 때 "EP### 크레딧 상한 N"을 주면 그 범위 안의 생성은 다시 묻지 않는다.
상한을 넘을 것 같으면 멈추고 묻는다. 사용량은 `renders.md`에 남긴다.

## 3. 요청 범위별 납품 기준

| 요청 | 기본 납품 | 완료 증빙 |
|---|---|---|
| 주제 추천 | 후보표, 추천 이유, 메인 줄거리, 근거 후보 | 후보마다 질문·전개·근거 수준이 보임 |
| 리서치·대본 | 팩트체크, 대본, 읽기용 원고, 변경·평가 | 핵심 주장과 버전, 남은 확인 사항 표시 |
| 스타일 비교 | 같은 장면 비교 시안과 평가, 선택 기록 | 비교 파일이 실제로 열림 |
| 정적 제작 패키지 | 대표 그림, 대본·콘티·시나리오, 클립 프롬프트, 타임라인, 썸네일·메타 초안 | 그림·클립·프롬프트 번호가 서로 맞음 |
| 영상 제작 | 나레이션, 채택 클립, 최종 MP4, SRT, QC, 판정 | 전체 재생·규격·판정 확인 |
| 업로드 메타만 | 복사용 메타(필요 시 썸네일) | 실제 대본과 설명·출처·표현 범위 일치 |

상태는 `제안`, `대표 선택`, `제작 기준`, `실측 전`, `파일 검수 완료`, `공개 확인`, `미확인`처럼
구체적으로 쓴다. '완료' 대신 무엇을 어디서 확인했는지 적는다.

## 4. 수정 요청이 오면 함께 확인할 것

| 바뀐 것 | 다시 확인할 것 |
|---|---|
| 사실·수치·어원 해석 | 팩트체크, 나레이션, 자막, 칩의 연도·기호, 제목·설명·고정 댓글 |
| 대본·발화 길이 | 읽기 원고, 블록 분할, 실측 타임라인, 클립 길이, 자막, 첫·끝 연결 |
| 스타일·인물·대표 그림 | 반복 등장 블록, 프롬프트 고정 문장, 첫·끝 프레임, 썸네일 |
| 모델·실행 경로 | 입력 형식, 지원 길이, 라이선스, 비용, 시험 클립, 렌더 큐 |
| 최종 파일·제목·게시 일정 | 버전·경로, 게시 기록 |

## 5. 자주 쓰는 요청 문장

| 요청 | 하는 일 |
|---|---|
| "새 편 주제 추천해줘" (분야·시즌 조건) | 1단계부터 |
| "새 편: <주제>" | 1단계(그 소재 안의 관점 비교)부터 |
| "<주제> 정적 패키지까지" | 1~5단계 |
| "<주제> 알아서 끝까지" | 1~9단계, 승인 항목만 질문 |
| "패키지로 제작" + 첨부 | 0단계 대조 후 6단계부터 |
| "이어서: EP###" | 0단계 → 그 편 `생성상태.md`의 '대표 확인 대기'부터 |
| "검수만: EP###" | 8단계 독립 평가 |
| "썸네일·메타 다시: EP###" | 9단계 |
| "성과 기록: EP###" + Studio 캡처 | 11단계 |
| "에이전트 점검" | `docs/runbooks/local-generation.md` §1 점검 루틴만 실행하고 보고 |

## 6. 원칙

- 창작 방향(주제·스타일·대본)은 에이전트가 임의로 정하지 않는다. 후보와 근거를 보여 주고 대표가 고른다.
- 한 번에 하나의 변수만 바꿔 비교한다.
- 확인한 결과만 "됐다"고 말한다.
- 이야기가 바뀌면 `BRIEF.md`부터 고친다.

## 7. 새 작품 시작

`productions/_template/`의 세 파일을 `productions/<종류>/<작품>/`으로 복사해 시작한다.

| 파일 | 소유하는 것 |
|---|---|
| `BRIEF.md` | 기획: 후보·브리프, 팩트체크, 대본, 블록표·스타일, 블록별 콘티·프롬프트, 업로드 메타 |
| `생성상태.md` | 현재 단계, 쓰는 버전, 대표 선택 기록, 다음 행동, 대표 확인 대기 |
| `renders.md` | 생성·편집·판정·납품 결과, 성과, 이번 편에서 배운 것 |

두 편 이상에서 반복된 교훈은 `craft/playbooks/`로, 대표 결정은 `private/decisions.md`로 옮긴다.
