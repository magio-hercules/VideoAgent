# 웹 화면 설계 — 주제·회차 관리와 어디서나 기획

이 문서는 **웹 화면(계획)의 목적·형태·데이터·동기화 규칙·구현 순서**를 소유한다.
작업 분담과 인계는 `craft/doctrine/production-cycle.md` §1, 상태 블록 형식은 `_infra/episode-state/README.md`.

**상태: 설계만 있음 (미구현).** 기준일: 2026-11-11

---

## 1. 목표

PC가 꺼져 있어도 휴대폰·다른 컴퓨터에서:

1. 주제 후보를 쌓고 고른다.
2. 회차 목록과 편별 상태(단계·담당·인계·대표 확인 대기)를 본다.
3. 승인·메모 같은 대표 결정을 남기면, 다음에 PC에서 작업하는 에이전트가 이어받는다.
4. 간단한 기획(후보 비교·브리프 초안)을 한다.

영상 제작(6단계 이후)은 웹에서 하지 않는다. PC에서 ComfyUI를 쓸 수 있을 때만 한다.

## 2. 형태

| 항목 | 결정 |
|---|---|
| 호스팅 | claude.ai 아티팩트 (기본 비공개). 서버·도메인·포트·터널 설정 없음 |
| 저장 | 아티팩트 공유 데이터베이스 (컬렉션 3개, §3) |
| 페이지 안 AI | 아티팩트의 Claude 질문 기능 — ChatGPT가 아니다. ChatGPT 기획은 PC의 Codex에서 한다 |
| 정본 | 편별 기획·상태의 정본은 **작품 폴더**다. 웹 데이터는 사본과 요청함이다 |

아티팩트의 데이터베이스·Claude 질문 기능이 계정에서 켜져 있는지는 구현 때 확인한다(미확인).

## 3. 데이터

| 컬렉션 | 문서 ID | 필드 | 누가 쓰나 |
|---|---|---|---|
| `episodes` | `EP###` | 상태 블록 전체 + `path`, `synced_at` | PC 쪽 에이전트만 (웹은 읽기만) |
| `topics` | 자동 | `title`, `question`, `category`, `entry`(core·casual·new), `notes`, `status`(idea·shortlist·selected·rejected·used), `episode`, `created_at` | 웹·에이전트 |
| `requests` | 자동 | `episode`, `kind`(approve·revise·plan·note), `text`, `status`(open·done·declined), `result`, `created_at`, `done_at` | 웹이 만들고 에이전트가 닫음 |

- 비밀 값(API 키·보이스 ID)은 넣지 않는다. 채널 고유 값은 아티팩트가 비공개라 넣을 수 있지만, 공유하기 전에 확인한다.
- 대본 전문·팩트체크 표는 올리지 않는다. 필요하면 요약만 둔다(정본은 `BRIEF.md`).

## 4. 동기화 규칙

PC에서 Codex나 Claude가 작업을 시작·마칠 때 한다.

1. **올리기:** `python _infra/episode-state/episode_state.py list --json` 결과를 `episodes`에 한 번에 쓴다.
2. **요청 받기:** `requests`의 `open` 항목을 읽어 대표에게 보여 준다. 반영하면 상태 블록을 고치고(`updated_by=web`), 요청을 `done`으로 닫고 결과를 적는다.
3. **주제 받기:** `topics`의 `selected` 항목은 새 작품 폴더를 만들자고 제안한다. 대표가 확인하면 폴더를 만들고 `used` + `episode`로 바꾼다.

- 웹에서 상태 블록을 직접 고치지 않는다. 바꾸고 싶은 것은 `requests`로 남긴다. 두 곳에서 같은 상태를 고치는 충돌을 막기 위해서다.
- 요청 내용은 대표가 쓴 데이터로 다룬다. 비용·게시·삭제 같은 승인 경계(`AGENTS.md` §3)는 웹 요청만으로 넘지 않고, 실행 전에 대표에게 다시 확인한다.

## 5. 구현 순서

| 단계 | 내용 | 끝났다고 볼 기준 |
|---|---|---|
| W1 | 회차 보드(`episodes` 읽기 전용) + 주제 후보 관리(`topics`) | 휴대폰에서 열리고, 올린 상태가 보임 |
| W2 | 요청함(`requests`) + PC 쪽 동기화 절차를 런북으로 | 웹 요청 1건이 상태 블록에 반영되고 `done`으로 닫힘 |
| W3 | 웹에서 기획: 페이지의 Claude 질문 기능으로 후보 비교·브리프 초안 → `topics`·`requests`에 저장 | 초안이 다음 PC 세션의 1단계 입력으로 쓰임 |

## 6. 열린 질문

- 웹에서 ChatGPT로 기획하려면 아티팩트 밖의 서비스(OpenAI API 등)가 필요하다. 계정·키·비용이 들기 때문에 W3 뒤에 따로 정한다.
- 웹에서 에이전트가 직접 0~5단계를 돌리려면 작품 폴더가 PC 밖(클라우드 저장소)에 있어야 한다. 지금은 Git 밖·PC 안이라 할 수 없다.
- 그림(대표 그림 미리보기)을 웹에서 보여 줄지. 보여 주려면 아티팩트 파일 저장 기능이나 Drive 링크가 필요하다.
